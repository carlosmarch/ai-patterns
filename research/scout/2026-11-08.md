## New candidates

### Voice Relay to a Working Agent `voice/voice-agent-relay`

**Job:** oversee · **Confidence:** medium · **Nearest:** `voice-orb` (Voice Orb)

A realtime voice call with a front-line voice agent that hands work to the coding agent, answers questions about its progress and speaks short updates while it runs.

**Behavior.** With the agent idle and the input empty, the Send slot becomes a waveform "Start voice chat" button. The person describes a change out loud; the voice agent hands it to the chat's coding agent. They keep talking while it runs, asking what changed in a diff or how a run is going, and hear short progress notes and a brief spoken summary on completion instead of the full written reply. The call can be muted or ended from outside the app (iOS Lock Screen Live Activity).

- **(a) AI-specific:** (a) Spoken oversight of a long-running agent: the person needs a way to delegate and follow work without reading output.
- **(b) Observed:** (b) Cursor changelog, 2026-11-06.
- **(c) Distinct:** (c) Voice Orb/Listening State/Live Transcript cover the conversation itself; here the voice agent is a relay with state about another agent's run, speaks progress and summarises results.

**Evidence**

- Cursor (2026-11-06) — https://cursor.com/changelog/voice-chat

  > Describe a change out loud, ask what an agent is working on, and hear updates as the work moves forward.

### Publish Gate `agents/publish-gate`

**Job:** trust · **Confidence:** medium · **Nearest:** `diff-summary` (Diff Summary Card)

Before an agent-built app goes live, automated and agent-based security checks run; failures go back to the agent to fix, and nothing is published until the person explicitly confirms.

**Behavior.** The person picks a domain and chooses to publish. Cursor runs deterministic rules plus agent review for issues such as exposed secrets. If a check fails, the agent says what it needs to fix. Only when checks pass can the person explicitly publish; admins can approve a blocked publish, add review rules and unpublish any app. Sharing is then scoped to people, groups or the team.

- **(a) AI-specific:** (a) Agents generate and ship code the person has not read, so a checkpoint must catch leaked secrets before release.
- **(b) Observed:** (b) Cursor changelog, 2026-11-05; GitHub Copilot Agent Merge waits on required checks, 2026-11-06.
- **(c) Distinct:** (c) Tool Approval gates individual actions and Diff Summary reviews code changes; this gates release of the whole artifact on a pass/fail check with admin override.

**Evidence**

- Cursor (2026-11-05) — https://cursor.com/changelog/build-live-apps

  > Nothing goes live until the checks pass and you explicitly publish the app.

- GitHub Copilot app (2026-11-06) — https://github.blog/changelog/2026-11-06-github-copilot-weekly-releases-november-2/

  > Set up Agent Merge directly from a pull request to have Copilot merge it when it’s ready. It now stays enabled while required checks or rules are pending.

### Rejected Prompt Restore `errors/rejected-prompt-restore`

**Job:** recover · **Confidence:** low · **Nearest:** `generation-error` (Generation Error)

When an agent refuses the first prompt of a session, the prompt goes back into the composer with the reason shown, so the person can fix it and resend without retyping.

**Behavior.** The person sends the opening prompt of a local agent session. If the agent rejects it, no empty or failed session is left behind: the text reappears in the composer, the rejection reason is shown with it, and the person edits and resends.

- **(a) AI-specific:** (a) An agent can decline a request for policy or capability reasons; the person needs to know why and keep their words.
- **(b) Observed:** (b) Devin Desktop (formerly Windsurf) v3.12.28, 2026-11-07.
- **(c) Distinct:** (c) Generation Error and Chat Bubble retry a failed reply; here the input itself is returned for editing, with the agent's reason, before a session exists.

**Evidence**

- Devin Desktop (2026-11-07) — https://docs.devin.ai/desktop/changelog

  > If a local agent rejects the first prompt, Desktop puts the text back in the composer and shows the reason. You can correct it and resend without retyping.
